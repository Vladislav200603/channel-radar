# ADR-002: Append-over-time snapshots з idempotent time bucket

- Статус: прийнято
- Дата: 2026-09-16

## Контекст

Перегляди, реакції й кількість підписників змінюються. Зберігати лише останнє значення —
втратити головну аналітичну властивість. Водночас scheduler і ручний retry можуть
повторити один збір.

## Рішення

- пост унікальний за `(channel_id, telegram_post_id)`;
- channel snapshot унікальний за `(channel_id, observed_bucket)`;
- post snapshot унікальний за `(post_id, observed_bucket)`;
- bucket за замовчуванням дорівнює одній UTC-годині;
- повтор у bucket оновлює точку, новий bucket додає точку.

## Наслідки

Retries не створюють дублікатів, графіки мають часові ряди, а кількість рядків
залишається контрольованою. Ми свідомо не обіцяємо точність усередині години. Якщо
потрібна детальніша гранулярність, `COLLECTION_BUCKET_MINUTES` змінюється конфігурацією.
