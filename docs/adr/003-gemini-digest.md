# ADR-003: Gemini digest як некритичний адаптер

- Статус: прийнято
- Дата: 2026-09-16

## Контекст

AI-шар обов'язковий, але free quota, timeout або provider outage не повинні робити
дашборд недоступним. На момент реалізації моделі, згадані в умові, вже deprecated.

## Рішення

Використати актуальну stable `gemini-3.8-flash` через REST adapter. Генерація запускається
окремою дією, отримує не більше 40 публічних постів за сім днів і зберігає лише успішний
результат. Provider/model задаються environment. Помилки повертаються як domain result,
а не exception до web layer.

Бюджет відповіді — 2048 output tokens. HTTP 200 сам по собі не означає успіх:
перевіряємо структуру JSON, `finishReason=STOP` і наявність змістовного завершеного
тексту. Обрізану (`MAX_TOKENS`), заблоковану або порожню відповідь не зберігаємо;
короткі вступи без дайджесту також відхиляються. Перевірка довжини й структури є
захистом від очевидно незавершених відповідей, а не гарантією фактичної точності.

Тимчасові HTTP-помилки, timeout і невалідний результат мають один повтор, далі —
резервну модель `gemini-3.5-flash-lite`. Кожна спроба обмежена 18 секундами,
а весь запит разом із паузами, повторами та fallback — 55 секундами. Помилки
авторизації не повторюються. Логи містять тільки модель, HTTP-статус і тип помилки,
без тіла відповіді провайдера чи ключів.

Prompt явно описує вибірку: до 40 текстових уривків довжиною до 800 символів;
відео, фото й аудіо не транскрибуються. Назва каналу й дописи передаються як
недовірені дані JSON із забороною виконувати вкладені інструкції. Це зменшує
ризик prompt injection, але не робить LLM джерелом перевірених фактів.

## Наслідки

- ingestion і звичайні сторінки не залежать від Gemini;
- попередній digest лишається доступним під час outage;
- prompt і response легко замінити іншим provider;
- Free Tier може використовувати публічний контент для покращення продуктів Google —
  це прийнятно лише тому, що в prompt немає приватних даних.
